110. Balanced Binary Tree

A tree is balanced when, at every node:

|left height - right height| ≤ 1

The interesting part is that we can't check this properly until we know both subtree heights.

So this becomes a post-order DFS problem:

left → right → current node

Each recursive call returns the subtree height:

return 1 + max(left, right)

And before returning, we check:

if abs(left - right) > 1:
    self.balanced = False

For the balanced example:

[3,9,20,null,null,15,7]

the root gets:

left = 1  
right = 2  
difference = 1 ✓

But in the unbalanced tree, eventually:

left = 3  
right = 1  
difference = 2 ✗

One DFS gives us both pieces of information: subtree heights and whether the tree is balanced.

Time: O(n)  
Space: O(h) for the recursion stack.

Reusable tree pattern:

When a parent's answer depends on information calculated from its children, think post-order DFS.

The children do the work first. The parent gets the report afterward. Very corporate.
