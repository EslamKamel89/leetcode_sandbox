86. Partition List

Linked lists are complicated enough. Now we have to separate them without messing up the order.

The trick? Two dummy heads and two separate lists.

Given:

head = [1,4,3,2,5,2]  
x = 3

We build two lists:

Left (< 3): 1 → 2 → 2  
Right (≥ 3): 4 → 3 → 5

Then connect them:

1 → 2 → 2 → 4 → 3 → 5

Done!

My approach:

- Create two dummy nodes.
- Traverse the original list once.
- Append each value to the appropriate partition.
- Connect both lists and return the new head.

Why dummy nodes?

They make building and connecting linked lists much cleaner, especially when one partition is empty.

And because we append in traversal order, the relative order stays intact.

Time: O(n)  
Space: O(n) — my solution creates new nodes rather than reusing the originals.

Key takeaway: When a linked list needs stable partitioning, build separate chains and connect them at the end.

Two lists, one traversal, zero sorting required.
