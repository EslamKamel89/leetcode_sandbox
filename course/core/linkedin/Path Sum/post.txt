112. Path Sum

A tree problem where the real question is:

“Can I reach a leaf with exactly the right amount of money left in my pocket?” 😄

For:

targetSum = 22

        5
       /
      4
     /
    11
      \
       2

The path is:

5 → 4 → 11 → 2 = 22

The DFS keeps a running sum:

curr_sum += node.val

Then we only check the answer when we reach a leaf:

if not node.left and not node.right:
    return targetSum == curr_sum

Why not check earlier?

Because the problem specifically asks for a root-to-leaf path. Reaching `22` at an internal node isn't enough.

The recursion explores both directions:

return dfs(node.left, curr_sum) or \
       dfs(node.right, curr_sum)

And the `or` gives us a nice property:

One valid path is enough.

For the example, DFS explores:

5 → 4 → 11 → 7
              ❌ 27

backtrack

5 → 4 → 11 → 2
              ✅ 22

Once the second branch succeeds, `True` propagates back through the recursive call stack.

Time: O(n)
Space: O(h) for the recursion stack.

The pattern to remember:

DFS + running state + check at the correct stopping condition.

Here, the stopping condition isn't just “reached a node.”

It's:

“Reached a leaf.” 🌳
